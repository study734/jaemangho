# 발견 콘텐츠 개편 검증

## 적용한 콘텐츠 기준

메시지 10개·3명이라는 기존 통계 조건을 발견의 재미로 취급하지 않는다. 완료된 주의 칭호를 우선하고 실제 수상자와 기록을 공개한다. 개념글은 반응 3개·답글 2개 이상, 합계 8개 이상이어야 한다. 대화 구간은 4명·30개 이상이며 같은 채널 직전 7일의 3명 이상 참여 구간 최소 6개 중앙값의 2배 이상인 경우만 선별한다. 비교 표본이나 참여자가 부족하면 제외한다. 본문·대화 주제·감정을 지어내지 않는다.

이 기준은 메타데이터로 설명 가능한 발견의 초기 선별 정책이다. 실제로 친구들이 재미를 느끼는지는 반응과 사용 경험을 통해 계속 검토해야 한다. 단순 통계가 자동으로 재미있는 사건이 되는 것은 아니다.

## 화면과 경험

- 홈 정리: 장식 궤도, 롤·커뮤니티의 생성 배경, Steam의 모바일 가상 요소 그림과 표지 기울임을 제거한다. 실행·검색은 한 영역으로 묶고 보조 기록은 구분선으로 정리한다. 실제 비교값의 그래프는 유지한다.
- 넓은 화면: 발견 약 61.8%, 짧은 실행 영역·Steam 검색 약 38.2%. 두 열 높이를 강제로 맞추지 않는다. 실행 패널 높이는 테스트에서 250px 미만, 검색은 첫 화면의 700px 이전에 진입한다.
- 1024px 이하: 발견 → 실행·Steam 검색. 모바일 발견은 그래픽과 본문을 한 열로 배치하며 제목은 단어 단위로 줄바꿈한다.
- 재순이: 원본 비율 이미지와 짧은 진행 문구로 카드별 질문 → 공개 후 응답을 이어준다. 반응·공유는 공개 후 표시하고 다음 발견을 강조한다. 공개 모션은 동작 줄이기 설정에서 꺼진다. 이미지가 실패해도 진행 문구가 남는다.
- 콘텐츠 보상: 실제 참여자 아바타를 흐리게 둔 질문 → 실제 얼굴과 주인공·결과 제목. 공개 후 질문 제목을 계속 남기지 않는다. 단독 인물은 PC에서 더 크게 표시하고 모바일에서는 얼굴·이름과 칭호·기록을 나란히 놓는다. 단독 칭호의 반복 문장은 모바일에서 생략하며 공개 후 다음 버튼이 하단 탭에 가리지 않는지 390×844 화면으로 검사한다. 비교 기록에는 실제 중앙값과 해당 구간의 막대를 표시한다. 없는 아바타는 이름의 첫 글자를 표시한다. 이미지가 서버 HTML에서 먼저 실패한 경우도 클라이언트 연결 시 상태를 확인해 대체한다.
- 빈 기록: 큰 게임 제안 포스터와 하나뿐인 콘텐츠의 이전·다음 조작을 제거한다. 게임 찾기는 유지한다.
- 요즘 우리: 메뉴 세 개 대신 선별된 칭호·개념글·비교 구간의 실제 기록. 개수와 종류를 채우기 위해 빈 콘텐츠를 만들지 않는다.
- 재밌다: DB에 멤버당 한 반응을 저장·취소한다. 다시 열어도 유지되고 중복 요청은 중복 집계되지 않는다.
- 공유: 사용자가 기기의 공유 창 또는 복사로 실행한다. 로그인한 친구는 해당 카드로 진입하며, 목록에서 사라졌다면 이를 안내한다. 자동 복사가 실패하면 직접 복사할 링크를 표시한다. 외부 메시지를 자동 전송하지 않는다.

## 자동 검사

- `npm run lint`: 모듈 경계를 유지한 상태로 통과.
- `npm test`: 로컬 격리 PostgreSQL에서 53개 파일, 342개 테스트 통과.
- `npm run build`: 타입 검사와 운영 빌드 통과. 운영용 인증 환경변수를 넣지 않은 독립 빌드에서는 기존 인증 설정 경고가 발생하며, E2E 빌드는 테스트 전용 설정과 DB를 사용한다.
- `npm run test:e2e`: 로컬 운영 빌드·격리 DB에서 Chromium 58개 중 57개 통과. 빈 기록 영역 제거에 맞춰 남은 테스트의 기대값을 수정했고, 해당 테스트와 최종 발견 흐름을 포함한 6개를 다시 실행해 모두 통과했다.
- `git diff --check`: 통과.

서버 테스트는 평범한 통계·부족한 비교 표본·낮은 반응의 제외, 인물과 칭호 우선순위, 동일 원문 중복 제거, 최신 완료 주의 공동 수상자, 과거 기록의 실제 날짜, 출처 실패·복구를 검증한다. DB 통합 테스트는 실제 중앙값·표본 수·참여자·아바타 연결과 반응의 중복·취소·다른 멤버·존재하지 않는 원문을 검증한다.

E2E는 공개 전 반응·공유 비노출, 재순이의 공개 전후 문구 전환, 다음 발견 강조, 동작 줄이기, 실제 테스트 기록 공개, 포커스 유지, 결과 접기, 각 카드로 이동, 반응 저장·재접속·취소, 공유 내용·링크 복사, 입력·동일 출처·로그인 검증, 없는 공유 카드와 반응·복사 실패를 확인한다. 기존 게임 검색·로그인·차단·관리자·프로필·게임 흐름도 실행한다.

## 실제 화면 캡처

`output/playwright/`의 캡처는 로컬 운영 빌드와 테스트 데이터로 만든 실제 화면이며 Git에 커밋하지 않는다.

- `home-long-name-*.png`, `home-long-member-*.png`, `home-member-image-failure.png`: 1504·1024·390·320px에서 긴 공백 없는 이름, 비정사각형 아바타와 로딩 실패.
- `discovery-before-1504.png`, `discovery-before-390.png`: 공개 전 재순이의 질문과 흐린 실제 아바타.
- `discovery-content-1504.png`, `discovery-content-1024.png`, `discovery-content-390.png`: 칭호 공개, 실제 연결 아바타, 기록·반응·공유, 실행 영역과 Steam 검색 배치.
- `discovery-reveal-mobile.png`: 390×844 공개 직후 상태, 키보드 포커스와 다음 버튼·하단 탭의 분리.
- `discovery-comparison-mobile.png`: 실제 비교값과 참여자, 긴 한국어 제목·이름.
- `discovery-loading-desktop.png`, `discovery-loading-mobile.png`: 집계가 느려도 실행·검색 영역이 먼저 표시되는 상태.
- `home-feed-failure.png`: 최근 활동 조회가 실패할 때의 별도 오류 안내.
- `discovery-empty-and-share-failure.png`: 빈 기록에서 게임 제안, 반응·공유 실패 안내와 직접 복사 링크.

네이티브 모바일 공유 창은 실제 기기에서 검증하지 않았다. 다수의 공동 수상자가 있는 긴 카드도 별도 시각 검증을 하지 않았다. 운영 Vercel 환경은 조작하거나 배포하지 않았다.

## 운영 반영과 후속 범위

반응에는 독립된 `0016_discovery_reactions.sql` 마이그레이션이 필요하다. 기존 배포의 마이그레이션 실행 경로로 빌드 전에 적용한다. 기존 로그인·접근 제어·수집 테이블·환경변수·배포 설정은 변경하지 않았다. 로컬 테스트 DB에만 적용했다.

추억 작성·영구 보관·Rewind·개인화는 구현하지 않았다. 게임 표지는 편집자의 제안이며 실제 멤버의 보유·플레이 기록으로 표현하지 않는다.

## Vercel 스킬 확인

`verification`과 `react-best-practices`의 기존 원칙을 유지한다. 홈 진입 → 서버 집계·맥락 → 선별 카드 → 공개 → 반응 저장·공유·게임·원문 이동을 확인한다. 출처별 성공 캐시, 요청별 조회 공유, 구역별 Suspense, 정적 홈 서버 렌더링, 포커스를 유지하는 펼침 버튼을 유지한다. 지연 검증은 서버 첫 홈 요청 전에 생성된 디스크 데이터 캐시를 비워 반복 실행 조건을 맞춘다.
