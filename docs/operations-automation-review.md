# 취미 프로젝트 운영 자동화 검토

검토일: 2026-10-11. 운영 목표는 인프라 지출 0원, 데이터 보존, 개발자가 처리해야 할 일의 최소화다. 무료 한도의 일시 중단·예약 지연을 허용하며 자동 유료 전환은 하지 않는다.

## 대시보드에서 판단할 순서

1. **지금 필요한 조치**: 앱 경고와 채팅 원인, 자동 복구 횟수·다음 시도 가능 시각을 확인한다. 다음 시각은 최소 대기 종료이며 실제 예약 실행 시각을 보장하지 않는다.
2. **자동 운영 보호**: 고정 저장소의 main에서 실행한 백업·보관 백업 복원·Smoke 결과와 마지막 성공을 확인한다. 백업·복원은 성공 실행에 해당하는 미만료 보관 파일도 있어야 정상으로 표시한다.
3. **무료 용량 보호**: 저장소의 보관 파일 크기를 확인한다. 목록이 일부면 하한으로 표시하고 공급자 사용량 조회 실패를 정상이나 0으로 취급하지 않는다.
4. **운영 로그와 연동 기록**: 구체적인 실행 ID·실패 단계·HTTP 상태·SQLSTATE를 확인한다.

넓은 화면과 모바일 모두 조치 → 보호 → 로그 순서의 한 열을 유지한다. 긴 한국어 진단·링크의 가독성을 우선하며 보호 항목은 구분선으로 나눈다. 사용자·연동·기록 탭의 기존 행동과 권한은 유지한다.

## 확인하고 개선한 자동화

- 관리자 운영 조회는 화면이 보일 때 60초 간격으로 실행하고 다시 보이면 즉시 갱신한다. 진행 중인 조회는 재사용해 수동 새로고침과 폴링의 중복을 막는다.
- 공개 자동화 메타데이터는 서비스 인스턴스에서 정상 조회를 한 시간 재사용하고 동시 요청을 합친다. API 오류는 15분 뒤 다시 확인한다. 원본 fetch와 관리자 응답은 `no-store`로 처리해 프레임워크 캐시와 서비스 캐시의 보관 시간이 겹쳐 오래된 결과를 최신으로 표시하지 않는다. 인스턴스 간 캐시는 공유하지 않으므로 콜드 스타트·여러 인스턴스에서는 외부 호출이 추가될 수 있으며 API 제한은 확인 불가로 표시한다. 개인 데이터·비밀값을 캐시하지 않는다.
- 복구 실행기 완료 후 10분 이내의 반복 요청은 최근 결과가 정상·대기·복구 불필요이고 새 채팅 실행이 없으면 `busy`로 생략한다. 성공 시각을 연장하지 않는다. 기존 실행 중 유일성 제약, 채팅 잠금과 재시도 상한을 유지한다.
- DB 크기와 과금 사용량을 분리했다. `pg_database_size`는 연결한 DB 크기이며 Neon 프로젝트의 전체 저장량·월 연산량이 아니다. 오래된 1GB 무료 한도 표시를 제거했다.
- 실행 성공은 보호 설정의 활성화를 증명하지 않는다. 특히 Smoke 성공만으로 자동 롤백 활성화를 표시하지 않는다. 최근 실패·생략, 이전 성공, 실행 중, 성공 기록 공백, 조회 실패를 구분한다.
- GitHub의 Dependabot 취약점 알림·자동 수정 PR을 활성화했다. npm·Actions 업데이트 PR은 매주 만들며 minor/patch를 묶고 열리는 PR 수를 제한한다. 보안 수정 PR은 일반 버전 업데이트 한도와 별도다. minor·patch 묶음(`minor-and-patch`, `action-updates`) PR만 필수 검사 통과 후 CI가 바로 머지(squash)하며(2026-11, [CI의 dependabot-merge](../.github/workflows/ci.yml); 비공개 무료 저장소라 GitHub 자동 머지 기능은 쓸 수 없다), 메이저 변경과 `security-fixes` 묶음은 사람이 머지한다. 도입 전 한 달간 minor·patch PR 7개 중 4개가 머지되지 못하고 새 PR로 대체됐다.
- Dependency review가 PR·merge queue에서 새 high/critical 취약점(개발 의존성 포함)을 검사한다. 기존 필수 `check`가 이 결과를 기다려 실패 시 머지를 막으므로 브랜치 보호 설정에 새 검사 이름을 추가할 필요가 없다.
- Neon Free의 프로젝트 스냅샷을 6시간마다 조회해 실제 CU-second·전송량을 보고한다. `NEON_API_KEY`는 Actions에만 등록하며 앱에는 최소 숫자·집계 기간·조회 상태만 기존 크론 인증으로 전달한다. 첫 성공 전에는 실제 활성화 완료라고 판단하지 않는다.
- 연산 100 CU-hour·전송 5 GB 예산의 80%에서 예약 채팅 수집·복구를 48시간에 한 번으로 감속하고 90%에서 중단한다. 중단은 75% 미만, 감속은 70% 미만의 새 성공 샘플에서 해제한다. 활성화 후 조회 실패·24시간 지난 샘플은 감속하며 이미 중단했으면 유지한다. 같은 기간 내 수치 감소·과거 보고로 제한을 풀지 않는다. 수동 수집은 관리자 결정으로 허용한다.

## 무료 운영 보호의 현재 범위

현재 보호는 DB를 깨우지 않는 5분 감시, 30분 DB·복구 점검, 채팅 자동 복구 6회·48시간 상한, 정상 캐시 재사용, 백업 파일 10MB 및 예상 보관량 400MB 제한이다. 백업 30일 보관, 매일 격리 복원, 주간 보관 파일 복원 검증을 유지한다.

GitHub 보관 파일의 현재 크기 합계는 계정 전체 과금값이 아니다. 다른 저장소·Packages와 시간별 누적 사용량은 계정 Billing에서 확인한다. 용량 보호는 업로드를 중단하며 기존 복구 자료를 자동 삭제하지 않는다.

## 아직 남은 점과 우선순위

1. **전체 사용량 보호 확대**: Neon 연산·전송량 보호는 운영 중이다(`NEON_API_KEY` 등록됨. 키가 없으면 실패하는 Free usage protection 워크플로가 2026-11 계속 성공). GitHub Actions 실행·과금 시간과 저장 용량은 같은 워크플로의 `scripts/measure-project.mjs`가 측정해 7일 보관 파일로만 남기며 주간 요약에는 넣지 않는다. Neon 프로젝트 저장량, Vercel CPU·전송량, Cloudflare 사용량은 자동 수집하지 않는다. 방문자 트래픽·다른 수집·백업·감시 사용량까지 자동 제어하는 기능이 아니므로 전체 무료 한도를 보장하지 않는다. 읽기 권한과 실제 플랜을 확인한 뒤 적용 범위를 늘려야 한다.
2. **주·보조 실행기의 완전한 역할 분리**: 10분 내 복구 재실행은 줄였지만 GitHub monitor와 recovery의 후속 점검, Worker의 점검은 여전히 일부 중복된다. 독립 실행기 장애를 감지할 증거 없이 보조 경로를 제거하지 않는다. 현재 외부 성공 시각은 실행기별 증거가 아니므로 Worker가 정상이라고 단정하지 않는다.
3. **조용한 주간 요약**: 구현했다(2026-11, [운영 절차](../OPERATIONS.md#운영-상태와-장애-알림)). 볼 것이 있는 주에만 무료 인프라 사용률·월말 추정과 경고·실패·개입을 한 번 보낸다. Vercel·Cloudflare 사용량은 자동 수집하지 않고, GitHub Actions 측정값은 보관 파일에만 있어 요약에 없다.
4. **무료 플랜을 넘는 경우**: 자동 업그레이드 대신 비필수 수집부터 줄인다. 운영 DB 복원·권한 변경·비밀키 변경·비용 결정은 사람이 처리한다. 현재 이 문서는 비용 정책 검토이며 계정 Billing 설정을 변경한 기록이 아니다.
