# 디스코드 게임추천의 Steam 연결을 최대한 줄이기

상태: 완료 <!-- #149 머지로 구현 -->
작성: 소유자(2026-11-21 세션 대화) · 정리: 에이전트 · 날짜: 2026-11-21
출처: 2026-11-21 추천 검토, intent/0004 이후 남은 웹 의존

## 문제
- `/게임추천`은 요청자뿐 아니라 **고른 친구 전원**이 사이트에 로그인해 Steam이 연결돼 있어야 한다(`games.ts`의 `resolvePlayers`, 코드로 확인). 멤버는 웹을 거의 쓰지 않는다.
- 웹에서 필요한 단계가 흩어져 있다: 로그인 → (디스코드 프로필에 Steam이 없으면) `/steam`에서 Steam 본인 확인 → `/steam` 동의. 끝난 뒤 디스코드로 돌아가라는 안내도 없다.
- 사이트 계정이 있어도 동의만 없는 사람도 웹에 다녀와야 한다.
- 실제로 어디서 얼마나 막히는지는 `discord_usage_blocks`(2번, 배포 전)로 측정할 예정이다. 지금은 측정 전이다.

## 원하는 결과
각자 처음 한 번, 디스코드 버튼에서 시작하는 한 화면(클릭 두세 번)으로 준비를 끝내고, 이미 계정이 있는 사람은 디스코드 안에서 동의까지 끝낸다. 연결 안 된 친구는 요청자가 버튼 한 번으로 불러온다.

## 영향 받는 사용자·시스템
디스코드 멤버, `src/server/discord-interactions`(게임추천·버튼), 새 웹 화면 `/connect/steam`, Steam OpenID 확인 경로, Steam 이용 동의.

## 제약
- Steam 본인 확인은 브라우저 절차라 웹을 완전히 없앨 수 없다. 디스코드에 Steam 주소를 입력받는 방식은 본인 확인이 없어 하지 않는다.
- 이용 동의는 웹과 같은 고지를 보여 주고 같은 기록(`acceptSteamConsent`)을 남긴다. 고지 문구는 한 곳에서 같이 쓴다.
- 로그인 판정(`auth.ts`)·관리자 판정은 바꾸지 않는다. 웹 로그인은 intent/0004의 사용 역할을 그대로 따른다.
- 새 환경변수·Cron 없음.

## 결정 기록
- 2026-11-21 (소유자): Steam 고지(`steam-notice.ts`)와 `/privacy/steam`의 예약 수집 문장을 실제 동작(하루 한 번 예약 수집, 무료 사용량 보호로 늦어질 수 있음)에 맞게 고친다. **고지 버전은 올리지 않는다**(`steam-common-v1`·`steam-activity-v2` 유지). 다시 동의받기·예약 수집 끄기와 비교해 고른 것이며, 이전 문구로 동의한 사람은 다시 묻지 않고 예약 수집도 계속된다.
- 2026-11-21 (소유자): "4번은 최대 최적화로". 한 화면 연결 링크, 디스코드 안 동의 버튼, 연결 안 된 친구 알림을 모두 한다. 친구 알림은 요청자가 버튼을 눌렀을 때만 그 친구들만 멘션 알림을 보내는 공개 메시지로 한다(에이전트 해석, 요청자 확인 단계를 둠).
