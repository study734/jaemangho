# 웹에 들어오지 않는 멤버도 디스코드에서 재순이를 알고 바로 쓰기

상태: 수락
작성: 소유자(2026-11-21 세션 대화) · 정리: 에이전트 · 날짜: 2026-11-21
출처: 2026-11-21 핵심 문제 점검(웹 열람 7일 0회 기록 #137, 사용량 집계 #147, 의견 경로 #146)

## 문제
- 개발 1순위는 디스코드이고 멤버는 웹을 거의 쓰지 않는다. 그런데 디스코드 명령은 모두 "사이트에 디스코드로 한 번 로그인한 멤버"만 쓸 수 있다(`handler.ts`의 `commandUser` 확인, 코드로 확인함).
- 그래서 `/의견`·`/기록`처럼 사이트 계정이 필요 없는 기능도 로그인 안내에서 끝난다. 명령을 알려도 첫 사용이 막힌다.
- 재순이 명령이 있다는 걸 알리는 경로가 없다. `/패치노트`는 직접 실행해야 보이고, 자동 게시는 주간 시상식뿐이다.
- 로그인하지 않은 멤버 수는 측정하지 않았다(운영 DB 미조회). 사용량 집계는 로그인 안내로 끝난 시도도 같은 횟수로 센다.

## 원하는 결과
서버 멤버는 웹에 들어가지 않아도 대부분의 재순이 기능을 바로 쓰고, 사용법과 새 기능은 재순이가 채널에 직접 알린다.

## 영향 받는 사용자·시스템
디스코드 멤버, `src/server/discord-interactions`(접근 확인·의견 저장), 시상식 게시 채널, 매일 운영 보조 점검, `member_feedback`.

## 제약
- 접근 제어 변경은 사전 확인 대상이다(AGENTS.md) — 아래 결정 기록으로 확인받았다.
- 사이트에서 차단된 계정은 계속 막는다. 사이트 계정이 없는 사람은 사이트에서 차단할 수 없으므로 디스코드 서버의 관리 기능을 따른다.
- 본인 Steam 연결·이용 동의가 필요한 기능(게임추천)과 관리자 명령은 웹 흐름이 필요해 그대로 둔다(README 기능 배치 기준).
- 새 환경변수·Cron·웹 화면 없이 한다. 자동 공지가 같은 내용을 여러 번 올리지 않아야 한다.

## 열린 질문
없음.

## 결정 기록
- 2026-11-21 (소유자): "웬만한 작업은 디스코드에서 바로 사용 및 접근 가능하게" 한다. 계정이 꼭 필요한 기능만 로그인 안내로 남긴다. 사이트 차단은 계속 적용한다.
- 2026-11-21 (소유자): 누가 쓸지는 소유자가 친구들에게 준 **디스코드 역할**로 정한다. 관리자가 `/운영 사용역할`로 역할을 고르고(환경변수 대신 DB, 바꾸기 쉬움), 사이트 계정 유무와 상관없이 모두에게 적용하며, 역할을 정하기 전에는 서버 멤버 모두 허용한다. **웹 로그인도 같은 역할로 제한**한다(로그인 변경, 사전 확인 받음). 서버 관리자는 역할이 없어도 통과한다(스스로 잠기지 않게 — 에이전트 제안).
- 2026-11-21 (소유자): 사용법·새 기능 공지는 "재순이가 알아서" 한다. 사람이 공지를 올리고 고정하는 안, 고정 공지와 새 기능 자동 게시를 함께 하는 안과 비교해 고른 것이다.
