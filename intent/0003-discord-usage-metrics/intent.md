# 디스코드 기능을 얼마나·몇 명이 쓰는지 알기

상태: 수락
작성: 소유자(2026-11-20 세션 대화) · 정리: 에이전트 · 날짜: 2026-11-20
출처: 2026-11-20 요구사항 점검

## 문제
- 개발 1순위는 디스코드인데(README 개발 우선순위), 디스코드 명령·버튼 사용을 세는 곳이 없다. 사용 데이터는 웹 열람(`page_views`)뿐이고 Vercel Web Analytics도 꺼져 있다(확인함).
- 그래서 무엇을 키우고 정리할지, `intent/0001`·`0002`가 효과가 있었는지, 게임추천 버튼이 느린지 판단할 근거가 없다.
- 친구 서버는 인원이 적어 한 사람이 많이 쓰면 횟수가 왜곡된다. 몇 명이 쓰는지도 필요하다.

## 원하는 결과
관리자가 `/개선`에서 디스코드 기능별 최근 7일 사용 횟수·증감·하루 사용자 수·평균 처리 시간을 본다.

## 영향 받는 사용자·시스템
관리자, `src/server/discord-interactions`, 운영 점검의 보존 정리, 새 집계 테이블.

## 제약
- 누가 무엇을 했는지 장기 기록을 남기지 않는다. 사용자 수를 세기 위한 디스코드 ID는 최대 이틀만 둔다.
- 첫 응답 전에는 DB를 쓰지 않는다(3초 규칙). 집계 실패가 사용자 응답을 바꾸지 않는다.
- 무료 DB를 새로 깨우지 않는다(이미 DB를 쓰는 처리 뒤에서만 기록).

## 열린 질문
없음.

## 결정 기록
- 2026-11-20 (소유자): 사용량 집계를 한다. 횟수만 세는 안, 사용자별 기록을 보관하는 안과 비교해 **횟수 + 하루 사용자 수(ID는 이틀 안에 삭제)** 로 한다 — 소규모 서버에서 횟수만으로는 왜곡되고, 사용자별 장기 기록은 개인정보 부담에 비해 필요하지 않다. 개선 우선순위 규칙(키우기·정리 검토)에 디스코드를 넣는 것은 2주 이상 데이터를 본 뒤 별도 intent로 한다.
