# 디스코드 사용량 집계 — 명세·계획

intent: [intent.md](intent.md)

## 요구사항
- R1. 디스코드 명령·버튼·선택·입력창 제출을 처리해 응답을 보낸 뒤, 시스템은 그 기능의 한국 시간 하루 집계(`discord_usage`)에 사용 1회와 처리 시간(ms)을 더한다. 기능 이름은 `/게임추천`, `게임추천 › 다른 추천`, `모집 › 참여`, `의견 제출`처럼 사람이 읽는 이름이다. 가입 안내·거절로 끝난 요청도 시도로 센다.
- R2. 같은 날 같은 기능을 처음 쓴 사람이면 시스템은 그 기능의 하루 사용자 수를 1 늘린다. 이를 위해 (날짜, 기능, 디스코드 ID)를 임시 테이블(`discord_usage_users`)에 두며, 매일 운영 점검에서 전날보다 오래된 행을 지운다(ID는 최대 약 이틀 보관).
- R3. 영구 집계에는 날짜·기능·횟수·하루 사용자 수·처리 시간 합계·최대값만 둔다. 사용자 ID·입력 내용·채널은 남기지 않는다. 365일이 지나면 지운다.
- R4. 입력창을 여는 첫 응답(`/의견`, `재순이에게 전달`)은 세지 않는다(첫 응답 전 DB 없음). 의견은 제출(`의견 제출`, `의견 제출 (메시지)`)을 센다.
- R5. 집계 기록이 실패해도 사용자 응답은 이미 끝났고 바뀌지 않는다. 실패는 `app_failures`의 `api/discord.usage`로 남는다.
- R6. 관리자가 `/개선`을 실행하면 시스템은 최근 7일 기능별 사용 횟수 상위 8개를 그 전 7일 대비 증감, 하루 최대 사용자 수, 평균 처리 시간과 함께 보여 준다. 사용이 없으면 이 절을 붙이지 않는다.

## 설계
- 새 `src/server/discord-interactions/usage.ts`: `actionName(interaction)`(순수 함수), `recordUsage(action, discordId, ms)`(임시 ID 삽입과 집계 갱신을 SQL 한 문장, CTE), `usageReport()`, `purgeUsage()`.
- `handler.ts`의 `completeInteraction`: 처리 시작부터 응답 결정까지 시간을 재고, 응답 전송 뒤 `recordUsage`. 실패는 잡아서 `reportFailure`.
- `admin.ts`의 `/개선`: 의견 절 앞에 사용 절을 붙인다.
- `monitor.ts` 보존 정리에 `purgeUsage()` 추가.
- 마이그레이션 `0029_discord_usage.sql`: 두 테이블만 추가(이전 버전 호환).
- 무료 한도: 하루 행 수 ≈ 기능 수(약 20) + 기능×사용자. 이미 DB를 쓴 요청 뒤 문장 하나. 환경변수·`vercel.json`·웹 화면 변경 없음.

## 우려 사항
- 하루 사용자 수는 날짜별 고유 값이라 7일 고유 사용자 수가 아니다. 그래서 "하루 최대 N명"으로 표시한다.
- 처리 시간은 응답을 정하는 데까지의 서버 시간이며 Discord 전달 시간·콜드 스타트는 포함하지 않는다.

## 범위 밖
개선 우선순위 규칙 반영, 웹 관리자 화면, 주간 요약, 사용자별 기록.
